# 0095. 小檔合併：好幾個小版本連同內容合成一則 `bundle`，不超過一個訊框

- 狀態：**已接受（Accepted，2026-10-19）**——使用者 2026-10-19 選定格式、大小、時機與限速計數；分組方式由 [ADR 0096](0096-bundle-by-actual-route.md) 修正（拆過收件人、有欠款的也合）
- 日期：2026-10-19
- 對應：ADR 0026（批次模式與中繼限速）、0058（`nodes`：只有版本資訊的合成）、0068（每收件人配額與簽收單）、0091（只限速積壓的收件人）；CinderSync ADR 0095

## Context

2026-10-19 CinderSync 實機升級後的同步測試：
- 手機開啟後有 41 個修改要經中繼補送給 B（手機的直連被 A 佔住，B 只能走中繼）；
- 開啟時的補送已經用完「每小時 120 則」的額度，使用者在手機上新加的一行跟著等了 46 分鐘。

根本原因：經中繼時，一個版本就是一則 `node`。一篇 3 KB 的筆記也佔一整顆 kind 1060（一個訊框 48,000 B）：
- 佔一次中繼寫入；
- 佔一份收件人配額；
- 佔一次批次模式的限速。

錨點 1 免費方案的每日寫入額度被用光（2026-10-16），也是同一件事。

已有的合成只有兩種，都不適用：
- `nodes`（ADR 0058）：只帶版本資訊、只送給輕量成員；
- P2P 批次串流（ADR 0026）：要能直連。

ADR 0091 否決過「新修改插隊」：額度會被插隊的吃掉，積壓的那台更慢。

## Decision

1. **新的訊息類型 `bundle`**：`{ type: 'bundle', from, items: [{ fileId, node, content? }] }`。
   - 線上格式：標頭的每一項是 `[fileId, 版本, 內容長度｜-1]`，內容依序接在標頭後面，要剛好用完。
   - 收端每一項照 `node` 的規則驗證：路徑安全、內容長度與雜湊相符、刪除與只走 P2P 的版本不帶內容。任何一項不合法，整則丟掉。
   - 一則最多 200 項（`MAX_BUNDLE_ITEMS`）。
   - 收到後逐項 `#receiveNode`，跟收到一則一則 `node` 一樣：合併、衝突、歷史、簽收都不變。
2. **能力宣告協商**：
   - 名單上宣告 `BUNDLE_CAPABILITY = 'vaultBundles'` 的裝置，由應用交給 `bundleDevices`，執行中用 `setBundleDevices` 更新。
   - 只在收件人**全部**看得懂、而且都不是輕量成員時才合；否則照舊一則一則送。
   - 預設空，等於 v0.67 的行為。舊版收到不認得的類型會丟掉，不會讀錯。
3. **一則不超過一個訊框**：編碼後最多 `FILE_CHUNK_BYTES - 512` 位元組。
   - 裝不下的那一項留給下一則，後面更小的還可以裝。
   - 比一個訊框大、或只走 P2P 的版本照舊單獨一則。
   - 不跨訊框，所以不必處理「收到一半」；簽收與重送都以一則為單位。
4. **平時就合，不只在批次模式**：
   - 送出時從佇列裡第一個要送的版本開始，把收件條件一樣、還沒送出的小版本依序裝進來。收件條件指 `to`、`owed`、`got`、`full` 都一樣。
   - 湊不到兩項就照舊送 `node`。
   - 按積壓拆過收件人、或帳滿被排除了收件人的那一項，照舊單獨送。
5. **一包算一則**：批次模式的每小時限速、每收件人配額都以實際送出的事件計。一包是一則、每位收件人一塊。
6. 寄件序號一則一個，`#noteRelaySent` 記下包裡的每一個版本，跟 `nodes` 相同。

## Alternatives Considered

- **擴充 `nodes` 帶內容**：舊版會把它當成只有版本資訊，再發索取、多一輪；一樣要能力宣告。
- **一則可以跨多個訊框**：要處理分塊重組與部分遺失，配額與簽收都變複雜；省下的事件數跟一個訊框的版本差不多。
- **只在批次模式補送時合**：平常一次改很多篇的寫入次數不變。
- **限速照版本數算**：積壓照樣慢，只省寫入與配額。

## Consequences

- ＋ 經中繼送大量小檔時，事件數大約降到原本的十幾分之一。實測模擬：
  - 3 KB 的筆記一則裝 14 篇；
  - 120 篇的補送在每小時 20 則的限速下，一小時內補完，沒合的時候要好幾個小時。
- ＋ 中繼寫入、收件人配額、限速等待一起下降；小修改被同一台的積壓拖住的時間跟著縮短。
- － 一則裡有一項壞掉，整則都丟掉，然後經摘要與索取補回來，跟一則 `node` 壞掉一樣。
- － 名單上只要有一台舊版，廣播的版本就照舊一則一則送，要等所有裝置都升級才有效果。
- 驗證：`tests/sync/vault/bundle.test.ts`（線上格式與驗證、合成、訊框上限、大檔照舊、有一台看不懂、預設不合、執行中更新、限速補送）。
