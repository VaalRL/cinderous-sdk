# 0002. 試算器：PRD 有公式的照算，沒有的由本 ADR 定義

- Status: Accepted
- Date: 2026-09-27
- 實作：`src/estimator.ts`；測試：`tests/estimator.test.ts`

## Context

PRD §5.4 定義了 `estimateResourceConsumption` 的介面、一部分公式，還有一份範例輸出。
但有幾個欄位沒有公式：本機儲存月增長、耗電分級、付費方案月費。
範例裡的中繼流量（123.8 MB）也和它自己的公式算出來的值（124.05 MB）對不上。

## Decision

**照 PRD 公式算的欄位**

- 扇出：
  - Cinder EK 固定 2 份（自封副本＋遠端）。
  - 雙棘輪為 `(M − 1) × D + (D − 1)`。
  - `M` 是群組人數（含自己），填 1 視為 1:1、也就是兩個人；對方的裝置數以自己的台數 `D` 估。
- 每則開銷：NIP-44 為 80 B；雙棘輪加後量子時，每則再加 2,272 B（ML-KEM-768 公鑰 1,184 B＋密文 1,088 B）。
  EK 的 ML-KEM 密文只在金鑰公告時出現，攤到每則可忽略。
- 流量：
  - 直連 = 事件數 × 打洞率 × payload。
  - 中繼 = 事件數 × (1 − 打洞率) × (payload + 每則開銷)。
  - 每月以 30 天、1 MB = 10⁶ B 計算。
- Cloudflare 免費層佔用率 = 每日事件數 ÷ 100,000。只有部署在 tier-2（Workers）時才計算；
  tier-0（公共中繼）與 tier-1（自架）為 0。

**本 ADR 自訂的欄位**

- 付費月費：超過免費層時，以 Workers 付費方案估算：月費 $5，含每月 1,000 萬次請求，
  超出部分每百萬次 $0.30。這是 2026 年的牌價，僅供試算。
- 本機儲存月增長 = 每日動作數 × 30 × (每則開銷 + 64 B 索引)。
  只算自己送出的密文與索引；內容本身假定存在應用自己的資料夾（例如筆記庫），不重複計算。
- 耗電分級只看每日事件數，因為每個事件都是一次加解密加一次網路往返：
  - ≤ 1,000：negligible
  - ≤ 10,000：low
  - ≤ 100,000：moderate
  - 其餘：heavy
- 跳過金鑰記憶體：雙棘輪為 2,000 把 × 240 B = 480 KB，與 PRD 範例一致；EK 為 0。
- 建議（固定三條規則）：
  - 雙棘輪且 10 人以上時，建議改用 EK，並附上事件減少的百分比。
  - 超過免費層時，建議自架、降低頻率或換成扇出較小的模式。
  - 打洞率為 0 且單筆超過 256 KB 時，建議開 TURN 或分塊續傳。

## Consequences

- PRD 範例的扇出、事件數、每則開銷、直連流量、免費層佔用率、跳過金鑰、耗電分級與建議，
  全部逐項吻合，已寫成測試。
- 中繼流量照公式是 124.05 MB（PRD 寫 123.8），本機儲存是 36.2 MB（PRD 寫 29.3，但沒給公式）；
  以本 ADR 為準。
- 試算只是決策參考，不是帳單；價格變動時改常數即可。
