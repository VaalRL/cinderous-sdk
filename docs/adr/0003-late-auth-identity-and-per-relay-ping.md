# 0003. 連線池補兩樣：事後設定 NIP-42 身分、逐座探針

- Status: Accepted
- Date: 2026-09-27

## Context

《辭職信》改用 SDK 時，發現它的連線池有兩件事是 SDK 做不到的：

1. **先開池、後有金鑰。** 遊戲一啟動就開連線池，玩家的金鑰要到進了多人畫面才知道。
   原本 SDK 的身分只能在建構時給。
2. **健康探針。** 它定期對每一座中繼送一個帶範圍的小查詢，量到 EOSE 的往返時間，
   用來判斷健康、降級或斷線，並決定目前用哪一座、主站恢復後何時切回。
   「連得上但不轉發」的站只有這樣才判得出來，單看 socket 狀態看不出來。

## Decision

- `setAuthIdentity(identity | null)`：換掉或拿掉回應 NIP-42 的身分。已經收過挑戰、還沒認證的連線會立刻補回覆；
  傳 `null` 之後就當匿名。（v0.1.1）
- `ping(url, filters, timeoutMs)`：只對那一座送 REQ，回傳到 EOSE 的毫秒數。
  - 被 `CLOSED`、逾時、中途斷線、沒連上都 reject。
  - 探針的事件不會進其他訂閱。
  - filter 要帶範圍（例如 `#t`），否則車道會回 `restricted`。
- `isAuthenticated(url)`：認證通過後，探針可以帶 `authors`，讓嚴格平面的具名訂閱政策也收。
- **健康策略不進 SDK**：各應用的切換規則不同（《辭職信》是 `@lwd/shared/nostr` 的 `applyProbe`）。
  SDK 只提供量測，策略留在應用。

## Consequences

- ＋ 《辭職信》可以保留原本的健康報告與切換行為。
- ＋ 其他應用也能用 `ping` 做連線品質指示。
- － 探針會多用一條訂閱名額，而且每次都算一則訊息，計入車道每條連線每分鐘 240 則的上限；
  探針間隔由應用決定，《辭職信》是 60 秒。
